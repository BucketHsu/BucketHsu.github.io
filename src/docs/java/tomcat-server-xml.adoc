== Tomcat 8 / Tomcat 9

[NOTE]
====
* Tomcat 8.5 與 Tomcat 9 在 Connector 設定上大致可共用。
* 若目前環境為 Tomcat 9 + Java 8，且系統運作正常，通常可先維持現況，不必為了升版而調整。
* HTTP/2 若要在 HTTPS 上真正生效，仍需留意 Java / ALPN / TLS 實作條件。
====

=== HTTP Connector

[source,xml,title="HTTP Connector (8080)"]
----
<!-- =========================================================
     HTTP Connector (8080)

     【用途】
     - 提供 HTTP 服務
     - 當系統有要求安全連線時，可導向 8443

     【效能 / 併發控制】
     maxThreads        : 300   → 同時可處理請求數
     maxConnections    : 8192  → 最大連線數（含 keep-alive）
     acceptCount       : 100   → 當連線忙碌時，OS 等待佇列大小
     minSpareThreads   : 20    → 預留閒置 thread

     【連線行為】
     connectionTimeout : 30000 → 30 秒未完成連線則關閉
     URIEncoding       : UTF-8 → 避免 query string 中文亂碼

     【壓縮設定】
     compression       : on    → 啟用 gzip
     compressionMinSize: 2048  → 小於 2KB 不壓縮
     useSendFile       : false → 避免大檔走 sendfile 後跳過壓縮
     compressibleMimeType :
         僅壓縮文字類型（HTML / JSON / JS / CSS / XML / 字型）

     【實務建議】
     - 若前面有 Nginx，可考慮將壓縮交給 Nginx
     - 若是純內網業務系統，maxThreads 300 通常可先作為起點
========================================================= -->
<Connector
    port="8080"
    protocol="org.apache.coyote.http11.Http11NioProtocol"
    redirectPort="8443"
    connectionTimeout="30000"
    minSpareThreads="20"
    maxThreads="300"
    acceptCount="100"
    maxConnections="8192"
    URIEncoding="UTF-8"
    useSendFile="false"
    compression="on"
    compressionMinSize="2048"
    compressibleMimeType="text/html,text/xml,text/plain,text/css,text/javascript,application/javascript,application/json,application/xml,font/otf,font/woff,font/woff2" />
----

== Tomcat 10

[IMPORTANT]
====
* Tomcat 10 是由 Java EE / `javax.*` 轉向 Jakarta EE / `jakarta.*` 的主要分界點。
* 若原系統為 Tomcat 9 以前的 `javax.servlet.*` 應用，通常不可直接無痛升級到 Tomcat 10。
* 官方指出，從 Tomcat 9 升到 Tomcat 10，規格 API 套件名稱已由 `javax.*` 改為 `jakarta.*`，應用程式需要重新編譯或轉換。
* 若只是 Connector / `server.xml` 設定，整體方向與 Tomcat 8.5 / 9 仍相近。
====

== 結論

[NOTE]
====
* Tomcat 8.5 與 Tomcat 9 的 Connector 設定大致可共用。
* 若目前為 Tomcat 9 + Java 8，且系統運作正常，通常可先不用動。Tomcat 9 仍支援 Java 8。
* Tomcat 10 是最重要的升級分界點，因為應用程式需由 `javax.*` 轉為 `jakarta.*`。
* Tomcat 11 以上除了 Jakarta 相容性外，還要求 Java 17 以上。
* 升級 major version 時，不建議直接整份複製舊版設定檔，應以新版本預設設定為基礎再逐步調整。
====

== HTTPS 憑證格式差異說明

[NOTE]
====
在 Tomcat / Java 世界裡，最常碰到的不是只有「副檔名」，而是：

* 這個檔案是不是 *keystore* 容器
* 裡面有沒有 *private key*
* 裡面是否包含完整 *certificate chain*
* Tomcat 要用的是 *keystore* 型式，還是 *PEM 檔拆開指定*

Tomcat 在 keystore 模式下，主要使用 `JKS`、`PKCS11`、`PKCS12`。另外也可使用 PEM 方式分開指定憑證檔與私鑰檔。:contentReference[oaicite:1]{index=1}
====

=== 你最容易搞混的幾個觀念

==== `.pfx` 跟 `.p12` 差在哪？

實務上可先把它們視為 *同一家族*。
兩者通常都是 `PKCS#12` 容器，裡面可以放：

* 伺服器憑證
* 中繼憑證 chain
* 私鑰

OpenSSL 直接說 `PKCS#12 files` 有時也被稱為 `PFX files`；Microsoft 文件也把 PKCS#12 與 PFX 視為對應格式。:contentReference[oaicite:7]{index=7}

工程上通常這樣理解就夠了：

* Windows / IIS 世界常看到 `.pfx`
* Java / OpenSSL / Linux 世界常看到 `.p12`

但本質通常都是 PKCS#12。:contentReference[oaicite:8]{index=8}

==== `.jks` 跟 `.p12` 該選哪個？

如果是 *新建*、而且你希望跨平台與工具互通性較好，通常 **優先考慮 `PKCS12`**。
因為 Oracle 文件明確指出，JDK 9 之後預設 keystore 類型已改成 `pkcs12`，這是跨平台標準；而 `JKS` 是 Oracle 提供的 Java 專有 keystore 格式。:contentReference[oaicite:9]{index=9}

但如果你現在是：

* Tomcat 9
* Java 8
* 系統已經用 `JKS` 正常跑

那就**不必為了格式而硬改**。
因為 Tomcat 本來就支援 `JKS` 與 `PKCS12`。:contentReference[oaicite:10]{index=10}

==== `.keystore` 是不是一種格式？

**不是。**

`.keystore` 很多時候只是檔名或慣例名稱，不代表它一定是 `JKS`。
Tomcat 文件指出，若沒有另外指定 `certificateKeystoreFile`，預設路徑會是執行 Tomcat 使用者家目錄下的 `.keystore`。但檔案真正格式仍要看 `certificateKeystoreType`、JVM 預設類型，或實際檔案內容。:contentReference[oaicite:11]{index=11}

==== `.pem` 跟 `.p12/.jks` 最大差異是什麼？

最大差異在於：

* `.p12/.jks` 是 **keystore 容器**
* `.pem` 是 **編碼格式**

PEM 本質上是 Base64 資料加上 header / footer。它可以承載：

* 憑證
* 私鑰
* PKCS#8 私鑰
* chain

所以你常會看到：

* `server.crt`
* `server.key`
* `fullchain.pem`

它們可能都是 PEM。:contentReference[oaicite:12]{index=12}

對 Tomcat 而言，若走 PEM 方式，通常是：

* `certificateFile`：伺服器憑證（PEM）
* `certificateKeyFile`：私鑰（PEM）
* `certificateChainFile`：中繼憑證鏈（PEM）

官方文件也說，`certificateFile` 與 `certificateKeyFile` 預設可放同一檔，但**不建議**。:contentReference[oaicite:13]{index=13}

=== 在 Tomcat 裡怎麼選比較實務？

==== 方案一：Tomcat 使用 PKCS12 / JKS（最像 Java 世界）

適合：

* 你主要是 Java / Tomcat 維運
* 憑證想包成單一檔案
* 習慣 `keytool`

[source,xml,title="Tomcat 使用 PKCS12 / JKS"]
----
<Connector
    port="8443"
    protocol="org.apache.coyote.http11.Http11NioProtocol"
    scheme="https"
    secure="true"
    SSLEnabled="true">

    <SSLHostConfig hostName="_default_" protocols="TLSv1.2">
        <Certificate
            certificateKeystoreFile="D:/ssl/server.p12"
            certificateKeystorePassword="changeit"
            certificateKeystoreType="PKCS12"
            certificateKeyAlias="tomcat" />
    </SSLHostConfig>
</Connector>
----

若你要用 JKS，通常只要把：

* `certificateKeystoreFile`
* `certificateKeystoreType="JKS"`

改掉即可。Tomcat 在 keystore 模式支援 `JKS`、`PKCS11`、`PKCS12`。:contentReference[oaicite:14]{index=14}

==== 方案二：Tomcat 直接使用 PEM

適合：

* 憑證本來就由 Nginx / OpenSSL 流程產生
* 你手上已有 `crt` / `key` / `chain` 檔
* 想和 Linux / Nginx 的憑證管理方式一致

[source,xml,title="Tomcat 使用 PEM"]
----
<Connector
    port="8443"
    protocol="org.apache.coyote.http11.Http11NioProtocol"
    scheme="https"
    secure="true"
    SSLEnabled="true">

    <SSLHostConfig hostName="_default_" protocols="TLSv1.2">
        <Certificate
            certificateFile="conf/ssl/server.crt"
            certificateKeyFile="conf/ssl/server.key"
            certificateChainFile="conf/ssl/chain.crt" />
    </SSLHostConfig>
</Connector>
----

Tomcat 官方文件明確支援這組屬性，而且要求這些檔案是 PEM 編碼。:contentReference[oaicite:15]{index=15}

=== 對你目前環境的建議

[cols="1,3",options="header"]
|===
|情境
|建議

|Tomcat 9 + Java 8，現有 `JKS` 已正常
|先不用動，維持 `JKS` 可接受。Tomcat 9 本來就支援。:contentReference[oaicite:16]{index=16}

|新系統、跨平台、未來要和 OpenSSL / Windows 交換
|優先考慮 `PKCS12`（`.p12` / `.pfx`）。JDK 9+ 預設也走 `pkcs12`。:contentReference[oaicite:17]{index=17}

|前面已有 Nginx，且憑證管理都用 `crt` / `key`
|可考慮直接用 PEM，和 Linux 常見作法一致。Tomcat 支援 PEM 檔指定。:contentReference[oaicite:18]{index=18}

|文件裡看到 `.keystore`
|先不要假設它一定是 JKS；它可能只是檔名。要再看 `keystoreType` 或實際內容。:contentReference[oaicite:19]{index=19}
|===

=== 一句話整理

* `.pfx` / `.p12`：通常都是 PKCS#12，適合裝「憑證 + 私鑰 + chain」的單一容器。:contentReference[oaicite:20]{index=20}
* `.jks`：Java 傳統 keystore，Tomcat / Java 8 世界很常見。:contentReference[oaicite:21]{index=21}
* `.keystore`：通常只是檔名，不代表格式。:contentReference[oaicite:22]{index=22}
* `.pem`Base64 包裝格式，不是單一憑證種類，可裝 cert、key、chain。:contentReference[oaicite:23]{index=23}

== Tomcat HTTPS 憑證設定（server.xml 寫法差異）

[NOTE]
====
Tomcat 在 `server.xml` 中設定 HTTPS 憑證，主要分為兩種方式：

1. Keystore 模式（JKS / PKCS12）
2. PEM 檔模式（CRT / KEY / CHAIN 分開）

不同副檔名（.jks / .p12 / .pfx / .keystore / .pem）在設定上的差異，
主要體現在是否使用「keystore 欄位」或「PEM 欄位」。
====

'''

===  JKS（Java KeyStore）

[source,xml,title="JKS 設定（.jks）"]
----
<Connector port="8443"
           protocol="org.apache.coyote.http11.Http11NioProtocol"
           SSLEnabled="true"
           scheme="https"
           secure="true">

    <SSLHostConfig hostName="_default_" protocols="TLSv1.2">
        <Certificate
            certificateKeystoreFile="D:/ssl/server.jks"
            certificateKeystorePassword="changeit"
            certificateKeystoreType="JKS"
            certificateKeyAlias="tomcat" />
    </SSLHostConfig>
</Connector>
----

【重點】

* 使用 `certificateKeystoreFile`
* 必須指定 `certificateKeystoreType="JKS"`
* 適用於 Java 傳統環境（Tomcat 8 / 9 + Java 8 常見）

'''

===  PKCS12（.p12 / .pfx）

[source,xml,title="PKCS12 設定（.p12 / .pfx）"]
----
<Connector port="8443"
           protocol="org.apache.coyote.http11.Http11NioProtocol"
           SSLEnabled="true"
           scheme="https"
           secure="true">

    <SSLHostConfig hostName="_default_" protocols="TLSv1.2">
        <Certificate
            certificateKeystoreFile="D:/ssl/server.p12"
            certificateKeystorePassword="changeit"
            certificateKeystoreType="PKCS12"
            certificateKeyAlias="tomcat" />
    </SSLHostConfig>
</Connector>
----

【重點】

* `.p12` / `.pfx` 在 Tomcat 設定上相同
* `certificateKeystoreType="PKCS12"`
* 建議新系統優先使用（跨平台標準）

'''

===  .keystore（舊預設寫法）

[source,xml,title=".keystore（實際仍為 JKS 或 PKCS12）"]
----
<Connector port="8443"
           protocol="org.apache.coyote.http11.Http11NioProtocol"
           SSLEnabled="true"
           scheme="https"
           secure="true">

    <SSLHostConfig hostName="_default_" protocols="TLSv1.2">
        <Certificate
            certificateKeystoreFile="/home/tomcat/.keystore"
            certificateKeystorePassword="changeit"
            certificateKeyAlias="tomcat" />
    </SSLHostConfig>
</Connector>
----

【重點】

* `.keystore` 只是檔名，不代表格式
* 實際格式由：
- JVM 預設
- 或 `certificateKeystoreType` 決定
* 不建議新專案使用此模糊寫法

'''

===  PEM（.pem / .crt / .key）

[source,xml,title="PEM 設定（憑證 + 私鑰 + chain 分開）"]
----
<Connector port="8443"
           protocol="org.apache.coyote.http11.Http11NioProtocol"
           SSLEnabled="true"
           scheme="https"
           secure="true">

    <SSLHostConfig hostName="_default_" protocols="TLSv1.2">
        <Certificate
            certificateFile="conf/ssl/server.crt"
            certificateKeyFile="conf/ssl/server.key"
            certificateChainFile="conf/ssl/chain.crt" />
    </SSLHostConfig>
</Connector>
----

【重點】

* 不使用 keystore
* 憑證 / 私鑰 / chain 分開指定
* 適合：
- Nginx / OpenSSL 生態
- Linux 常見憑證部署方式

'''

|===
|格式
|是否 keystore
|server.xml 欄位

|Java 傳統格式

|.p12 / .pfx

|certificateKeystoreFile + type=PKCS12

|.keystore
|是（但不明確）

'''
