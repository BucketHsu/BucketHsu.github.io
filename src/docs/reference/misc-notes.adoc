== 網路服務狀態說明

image::HTTP_Status_Codes.png[width=1500, title=, Zoomable Image, link=../images/HTTP_Status_Codes.png, window=_blank, opts=nofollow]

=== ✅ 成功 (Successful)

[cols="1,3", options="header"]
|===
| 狀態碼
| 說明

| 200 OK
| 請求成功，伺服器成功回應所請求的資源。

| 201 Created
| 請求成功，並已建立新的資源（通常用於 POST 請求）。

| 204 No Content
| 請求成功，但伺服器不返回任何內容（常用於 PUT 或 DELETE 請求）。
|===

=== 🔁 重定向 (Redirection)

[cols="1,3", options="header"]
|===
| 狀態碼
| 說明

| 301 Moved Permanently
| 所請求的資源已永久搬移到新位置，請使用新的 URI。

| 302 Found
| 所請求的資源暫時搬移至其他位置，請依舊使用原 URI 再發送請求。
|===

=== ❌ 客戶端錯誤 (Client Error)

[cols="1,3", options="header"]
|===
| 狀態碼
| 說明

| 400 Bad Request
| 請求格式錯誤，伺服器無法理解該請求。

| 401 Unauthorized
| 未經授權，請求需提供身份驗證資訊。

| 403 Forbidden
| 伺服器理解請求但拒絕執行（無權限）。

| 404 Not Found
| 請求的資源不存在。
|===

=== ❌ 伺服器錯誤 (Server Error)
[cols="1,3", options="header"]
|===
| 狀態碼
| 說明

| 500 Internal Server Error
| 伺服器發生內部錯誤，無法完成請求。

| 501 Not Implemented
| 伺服器不支援該請求所需的功能。

| 502 Bad Gateway
| 伺服器作為閘道，收到無效回應。

| 503 Service Unavailable
| 伺服器暫時無法使用，可能因為過載或維護中。

| 504 Gateway Timeout
| 作為閘道的伺服器等候回應逾時。
|===

== 🌐 HTTP Request Methods

image::HttpRequestMethod.jpg[width=1200, title="Top 9 HTTP Request Methods", link=../images/HttpRequestMethod.jpg, window=_blank, opts=nofollow]

[cols="1,3", options="header"]
|===
| 方法 | 說明

| GET
| 取得單一或多筆資料。**只讀取**，不會改變伺服器狀態。

| POST
| 新增資料。常用於建立新的使用者、訂單。

| PUT
| 更新資料（整筆更新）。

| PATCH
| 局部更新資料（部分欄位修改）。

| DELETE
| 刪除資料。

| HEAD
| 與 GET 類似，但**不回傳 body**，常用於檢查資源是否存在。

| CONNECT
| 建立與伺服器的雙向連線（常見於 Proxy）。

| OPTIONS
| 回傳伺服器支援的方法清單（CORS 常用）。

| TRACE
| 偵錯用，回傳請求內容作 loop-back 測試。
|===

== Bash 語法小抄

image::Bash_Script_Basics.jpg[width=1500, title=, Zoomable Image, link=../images/Bash_Script_Basics.jpg, window=_blank, opts=nofollow]

=== 🖥️ Bash Script 基礎語法對照表

[cols="1,3", options="header"]
|===
| 類別
| 說明

| Shebang Line
| `#!/bin/bash`：告訴系統使用哪個解譯器來執行腳本

| Variables
| `username="Jay"`、`filename=$3`：宣告變數與取得參數值

| User Input
| `read -p "Enter your username:" user`：從終端機讀取使用者輸入

| Conditional if Statement
| `if [ "$EUID" -ne 0 ]; then ... fi`：條件判斷是否為 root 使用者

| For Loop
| `for i in {1..5}; do ... done`：從 1 數到 5 的迴圈

| Functions
| `function greet() { ... }`：定義函式，並以 `greet "Alice"` 呼叫

| Conditional Case Statement
| `case $num in 1) ... ;; esac`：根據輸入執行不同邏輯的條件分支

| File Operations
| `if [ -e "$filename" ] && [ -d "$filename" ]; then ...`：檢查檔案是否存在且為資料夾

| Command Line Arguments
| `$1`、`$2`：第一與第二個參數值

| Exit Status Codes
| `echo "Exit status: $?"`：顯示上一個指令的結束狀態碼

| Indexed Arrays
| `fruits=("Apple" "Orange" "Banana")`：使用數字索引的陣列

| Associative Arrays
| `declare -A capitals`、`capitals[USA]="Washington D.C."`：使用鍵值的陣列

| Command Substitution
| `current_date=$(date)`：執行指令並將結果指定給變數

| Command Line Redirections
| `echo "text" > example.txt`、`find ... 2> /dev/null`：輸出與錯誤導向處理

| Arithmetic Operations
| `expr 1 + 2`：執行整數加法運算

| Parameter Expansion
| `SRC="/path/to/foo.cpp"`、`BASEPATH=${SRC%/*}`：路徑變數取代與裁切

| Process Signal Handling
| `trap 'echo "收到 SIGTERM，清理中..."' EXIT`：攔截信號並處理（如 SIGTERM）

| Comments
| `# 單行註解`、多行註解以多行 `#` 表示
|===

== Linux 家族樹

image::LinuxTree.png[width=1920, title=, link=../images/LinuxTree.png, window=_blank, opts=nofollow]

=== 🐧 核心概念

* Linux：圖最上方的「Linux」指的是 Linux Kernel（核心），也就是作業系統的引擎。
* 所有的發行版（Debian、Red Hat、Arch、Gentoo…）都在這個核心之上，加入不同的工具、軟體管理方式和預設設定，形成各自的特色。

=== 🚀 五大主流家族

. Debian 系列
* 特點：穩定、套件數量龐大，適合伺服器，也有桌面版。
* 子系：
** Ubuntu：最受歡迎，對新手友善，桌面與雲端應用廣泛。
** Kali Linux：專門做資安與滲透測試。
** Parrot OS：跟 Kali 類似，但更強調隱私與匿名。
** Pure Debian：原始的 Debian，本身也可以當桌面或伺服器系統。
. Red Hat 系列
* 特點：商業與企業級，穩定、安全、長期支援。
* 子系：
** Fedora：前沿，測試新功能，之後會進入 Red Hat。
** CentOS（舊）：以前是免費 Red Hat 克隆版，用在伺服器很穩。
** Alma Linux：CentOS 停止之後，社群接手的新替代方案。
. Slackware 系列
* 特點：歷史最悠久，跟 UNIX 很接近，維持傳統。
* 子系：
** Slackware OS：原始風格，幾乎不改變。
** Salix OS：更簡單、對使用者友善一點。
. Arch Linux 系列
* 特點：極簡、DIY，你要什麼自己裝什麼，滾動更新。
* 子系：
** Manjaro：幫新手準備好，開箱即可用。
** EndeavourOS：介於純 Arch 和 Manjaro 之間，簡單但保留 Arch 精神。
** Black Arch：專為駭客與資安用途的 Arch 版本。
. Gentoo 系列
* 特點：完全自定義，一切從原始碼編譯，效能最佳化。
* 子系：
** Gentoo OS：主幹版。
** Funtoo：社群改良版，更快、更靈活。

=== 📌 總結

* Debian → 最穩定，適合伺服器、Ubuntu 普及桌面。
* Red Hat → 企業與商業使用，伺服器主力。
* Slackware → 老派玩家與懷舊用。
* Arch → 極簡主義，愛折騰的人最愛。
* Gentoo → 硬派玩家、效能調校達人專屬。

== 🐧 Linux 根目錄資料夾說明

[cols="1,3", options="header"]
|===
| 資料夾
| 說明

| `/bin`
| 必要指令，包含如 `ls`, `cp`, `bash` 等系統開機所需工具。

| `/boot`
| 開機核心與 bootloader 設定檔，如 `vmlinuz`、GRUB。

| `/dev`
| 裝置檔案，例如硬碟 `/dev/sda`、終端機 `/dev/tty`。

| `/etc`
| 系統設定檔儲存處，如 `/etc/hosts`, `/etc/passwd`。

| `/home`
| 使用者家目錄，如 `/home/user`。

| `/lib`, `/lib64`
| 執行基本指令所需的函式庫（libc、libm 等）。

| `/media`
| 自動掛載裝置（如 USB、光碟）的位置。

| `/mnt`
| 手動掛載裝置（如 NFS、ISO）的暫用掛載點。

| `/opt`
| 第三方應用程式安裝位置，例如 `/opt/google/`。

| `/proc`
| 虛擬檔案系統，提供系統與程序資訊，如 `/proc/cpuinfo`。

| `/root`
| root 使用者的家目錄（非 `/home/root`）。

| `/run`
| 系統開機後建立的暫存 runtime 資訊，如 PID、socket 等。

| `/sbin`
| 系統管理指令，如 `fsck`, `reboot`，多需 root 權限。

| `/srv`
| 服務用資料（如 Web 或 FTP 的資料根目錄）。

| `/sys`
| 設備與核心資訊的虛擬檔案系統（sysfs）。

| `/tmp`
| 暫存資料夾，所有使用者可寫入，系統重啟會清除。

| `/usr`
| 使用者程式與函式庫的儲存地。

| `/usr/bin`
| 一般應用程式的執行檔。

| `/usr/sbin`
| 非核心的系統管理工具。

| `/usr/local`
| 手動編譯或安裝的軟體會放在這裡。

| `/var`
| 可變動資料，如 log、快取、郵件、spool 等。

| `/var/log`
| 系統與應用的 log 檔，例如 `/var/log/syslog`。
|===

== SQL JOIN 說明小抄

image::SQL_JOIN_MEMO.jpg[width=1500, title=, link=../images/SQL_JOIN_MEMO.jpg, window=_blank, opts=nofollow]

=== 🔗 INNER JOIN（內部連接）

[cols="1,3", options="header"]
|===
| 語法
| 說明

| SELECT *
FROM A
INNER JOIN B ON A.key = B.key
| 只返回 A 與 B 中符合條件的交集資料（A ∩ B）
|===

=== 🔁 FULL OUTER JOIN（全外部連接）

[cols="1,3", options="header"]
|===
| 語法
| 說明

| SELECT *
FROM A
FULL JOIN B ON A.key = B.key
| 返回 A 與 B 所有資料，包含交集與各自的補集（A ∪ B）
|===

=== ❓ FULL OUTER JOIN 中的 NULL（差集：僅 A 或僅 B）

[cols="1,3", options="header"]
|===
| 語法
| 說明

| SELECT *
FROM A
FULL JOIN B ON A.key = B.key
WHERE A.key IS NULL OR B.key IS NULL
| 返回 A 與 B 中**不符合** JOIN 條件的資料（補集：只在 A 或 B 中）
|===

=== ⬅️ LEFT JOIN（左外部連接）

[cols="1,3", options="header"]
|===
| 語法
| 說明

| SELECT *
FROM A
LEFT JOIN B ON A.key = B.key
| 返回 A 所有資料，若在 B 中無對應則為 NULL（A ∪ A ∩ B）
|===

=== ➡️ RIGHT JOIN（右外部連接）

[cols="1,3", options="header"]
|===
| 語法
| 說明

| SELECT *
FROM A
RIGHT JOIN B ON A.key = B.key
| 返回 B 所有資料，若在 A 中無對應則為 NULL（B ∪ A ∩ B）
|===

== OSI 層的網路協議

image::NetworkingProtocols.png[width=1500, title=, link=../images/NetworkingProtocols.png, window=_blank, opts=nofollow]

=== 應用層 (Application Layer – 使用者級服務)

* FTP (Port 21) → 檔案傳輸協定 (File Transfer Protocol)
** 常用於檔案上傳/下載，純文字傳輸，資料與密碼容易被攔截，不安全。
* SSH (Port 22) → 安全遠端登入 (Secure Shell)
** 加密的終端連線，常取代 Telnet、FTP。
* TELNET (Port 23) → 遠端登入 (不安全)
** 明文傳輸，已不建議使用。
* SMTP (Port 25) → 郵件傳送 (Simple Mail Transfer Protocol)
** 用來發送電子郵件 (通常搭配 MTA，例如 Postfix)。
* DNS (Port 53) → 網域名稱系統 (Domain Name System)
** 負責將網址轉換成 IP 位址。
* HTTP (Port 80) → 網頁傳輸 (Hypertext Transfer Protocol)
** 傳統的網頁協定，不加密。
* POP3 (Port 110) → 郵件接收 (Post Office Protocol v3)
** 用來下載郵件到本地端。
* HTTPS (Port 443) → 加密網頁傳輸 (HTTP Secure)
** HTTP over TLS/SSL，安全的網頁存取。
* MTP → 媒體傳輸協定 (Media Transfer Protocol)
** 微軟延伸的檔案傳輸方式，用於相機/手機等設備傳檔，非網路核心協定。
* QOTD (Port 17) → Quote of the Day
** 一個非常古老的測試用協定，會回傳一段文字，現今幾乎不用。

=== 傳輸層 (Transport Layer – 端對端溝通)

* TCP → 傳輸控制協定 (Transmission Control Protocol)
** 提供可靠傳輸，三向交握、封包排序、重送確認。
* UDP → 使用者資料包協定 (User Datagram Protocol)
** 無連線、低延遲，常用於影音串流、DNS 查詢。

=== 網路層 / 資料連結層 (Network & Data Link Layer – 位址與交付)

* ARP → 位址解析協定 (Address Resolution Protocol)
** 用來把 IP 位址轉換成 MAC 位址 (IPv4)。
* RARP → 反向 ARP (Reverse ARP)
** 已被 BOOTP、DHCP 取代，用於透過 MAC 查詢 IP。
* PPP → 點對點協定 (Point-to-Point Protocol)
** 廣泛用於撥接網路、專線連線，支援驗證、壓縮。

== Java 專案的標準分層架構

image::javaCodingStandard.jpg[width=1500, title=, link=../images/javaCodingStandard.jpg, window=_blank, opts=nofollow]

[source, text]
----
projectname
 ├── src
 │   ├── main
 │   │   ├── java
 │   │   │   └── com.companyname.projectname
 │   │   │       ├── controller    → 處理 REST API 請求與回應，負責路由與輸入驗證
 │   │   │       ├── service       → 商業邏輯層，封裝流程與規則，避免控制器直接碰資料存取
 │   │   │       ├── repository    → 資料存取層（JPA Repositories），與資料庫互動
 │   │   │       ├── model         → 領域實體（Entities, JPA），對應資料表
 │   │   │       ├── dto           → 資料傳輸物件（Data Transfer Objects），用於 I/O 隔離模型
 │   │   │       ├── mapper        → 物件轉換（MapStruct 或自訂 Mapper），如 Entity ↔ DTO
 │   │   │       ├── config        → Spring 設定（如 SecurityConfig、CORS、ObjectMapper、Beans）
 │   │   │       ├── exception     → 自訂例外與全域例外處理（ControllerAdvice / Handler）
 │   │   │       ├── util          → 工具/輔助類別（共用函式、常數、共用元件）
 │   │   │       └── security      → 認證與授權（Filter、Provider、JWT/Sessions、ACL）
 │   │   │
 │   │   └── resources
 │   │       ├── application.yml   → 主要設定檔
 │   │       ├── static            → 靜態資源（JS、CSS、images）
 │   │       ├── templates         → 模板（Thymeleaf / FreeMarker）
 │   │       ├── i18n              → 多語系資源
 │   │       └── log               → 日誌輸出目錄（若有設定到檔案）
 │   │
 │   └── test                      → 測試程式（結構建議鏡像 main/java）
 │       └── java
 │           └── com.companyname.projectname
 │               ├── controller
 │               └── service
 │
 ├── target                       → 編譯產物（classes、測試報告、打包成品）
 ├── pom.xml                      → Maven 設定
 ├── .gitignore                   → Git 忽略清單
 └── README.md                    → 專案說明與操作指引

== Spring Boot Profile 常見用途

Spring Boot 支援以 `application-{profile}.yaml` 來區分不同環境。
以下為常見 Profile 的用途與對應部署位置：

[cols="1,3,3", options="header"]
|===
| Profile 名稱 | 常見用途 | 部署位置

| *default*
| 預設設定檔（base/common），放置所有環境共用設定，例如：系統名稱、序列化規則等
| 適用於所有環境，無特定限制

| *dev*
| 開發用，通常 DB 連線指向測試資料庫、開啟 debug log、允許 CORS 全開
| 開發者本機，或公司內部 Dev server

| *test*
| 測試用（整合測試、CI/CD pipeline）
| CI/CD server、QA 測試環境

| *sit / uat*
| 系統整合測試 (System Integration Test) / 使用者驗收測試 (User Acceptance Test)，模擬正式環境
| 公司內部 SIT/UAT 測試機

| *stage / preprod*
| 上線前的預備環境，設定與正式幾乎相同
| Staging server

| *prod*
| 正式環境，安全性設定最嚴謹，Log、快取、DB 都是 production
| 客戶正式環境
|===

== 前端架構名詞說明

[width="100%",cols="1,2,2",options="header"]
|===
|名詞 (含音譯) |說明 |由來比喻

|CSR +
(希艾斯阿爾 / Client-Side Rendering)
|由「瀏覽器」進行渲染，HTML 初始幾乎是空的，前端 JS 載入後再從 API 抓資料並組成畫面。SPA 常見模式。
|像買到 DIY 家俱扁箱，零件都在瀏覽器端，必須由使用者自己現場組裝好才能看到完整成品。

|SSR +
(艾斯艾斯阿爾 / Server-Side Rendering)
|由「伺服器」先把頁面渲染好，再把完整 HTML 傳給瀏覽器。前端框架（Next.js、Nuxt 等）可支援此模式。
|像餐廳直接端上已煮好的套餐，客人一坐下就能立即看到完整成品。

|SSG +
(艾斯艾斯吉 / Static Site Generation)
|在建置階段就把所有 HTML 頁面預先產生，部署後為真正靜態檔，讀取速度快且 SEO 佳。
|像預先做好的便當，出餐超快，但內容若要更新，需要重新製作一批便當。

|SPA +
(艾斯披耶 / Single Page Application)
|整站僅有一個 HTML，頁面切換全部靠前端 router 實作。常伴隨 CSR 或 SSR Hydration。
|像一張可變形的單頁布景板，透過前端動態更換區塊呈現不同情境。

|MPA +
(艾姆披耶 / Multi-Page Application)
|每次換頁都重新向後端請求新的 HTML。傳統 MVC（Spring MVC）多屬此類。
|像旅館，每切換一個房間就換一把鑰匙與全新房間，不是在同一空間移動。

|Hydration +
(海卓任 / 注水)
|SSR/SSG 產生的 HTML 初始無互動，前端 JS 載入後會將事件與邏輯「綁回去」，使畫面可互動。
|像買到模型展示品，外觀已經完整，但必須注入電池後才會動。

|SEO +
(艾斯伊歐 / Search Engine Optimization)
|使網站更易被搜尋引擎索引。SSR/SSG 有利 SEO，CSR 對 SEO 較不友善。
|像在圖書館裡，把你的書放在最容易找到的位置，標籤清楚才能被快速找到。

|BFF +
(比艾夫艾夫 / Backend for Frontend)
|專為前端服務的後端層，用於整合多個後端 API，減輕前端複雜度。
|像餐廳裡的專屬端盤員，負責幫你把後廚多道菜整合成一盤端上來。

|API Gateway +
(艾屁艾 蓋特威)
|API 的統一入口，可做身分驗證、流量管理、負載平衡等功能。
|像機場的海關入口，所有人都必須先經過這個管制點才能進入。

|Edge Rendering +
(埃極 任德林)
|由 CDN 節點（如 Cloudflare、Vercel Edge）在靠近使用者的位置進行 SSR 產生 HTML。
|像在你家附近的廚房準備餐點，不用再從遠端主廚那邊運送而來。

|Streaming SSR +
(斯特里明 艾斯艾斯阿爾)
|SSR 的推進版，允許伺服器分段把 HTML stream 給瀏覽器，使用者能更快看到部分內容。
|像邊上菜邊吃，不用等全部做完才能開始享用。

|CDN +
(希迪恩 / Content Delivery Network)
|將靜態資源分散至全球節點供使用者快速讀取。
|像便利商店，把商品放在每個街角，越接近你越快拿到。

|Routing +
(羅汀 / 路由)
|前端負責解析 URL 並切換畫面；後端 API 也有自己的 routing 定義。
|像捷運路線圖，每條線指定行進方向，決定從哪裡進到哪裡。

|===

== SELinux 與 container_file_t 說明

在 RHEL / AlmaLinux（SELinux Enforcing）的環境中，容器僅能讀寫
被標記為 `container_file_t` 的主機目錄。若目錄未貼上正確的 SELinux
Label，即使檔案權限為 777，容器仍會顯示 Permission denied。

檢查 SELinux Label：

[source,bash]
----
ls -Zd /opt/ntpclandfx-build
----

常見輸出：

----
unconfined_u:object_r:container_file_t:s0
----

其中最重要的是第三段的 Type：`container_file_t`。

若目錄標記為 `default_t`、`usr_t` 等類型，容器會拒絕存取。

將目錄標記為容器可用：

[source,bash]
----
sudo chcon -Rt container_file_t /opt/ntpclandfx-build
----

或使用 Podman volume 的自動 relabel：

[source,yaml]
----
volumes:
  - /opt/ntpclandfx-build:/usr/share/ntpclandfx-main:Z
----

使用 `:Z` 時，需以 `podman compose down` 後再 `podman compose up`
才會重新套用 SELinux Label。
