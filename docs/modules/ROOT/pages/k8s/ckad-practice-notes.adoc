== 考試紀錄

=== PSI 考試流程與注意事項

==== 考前與報到流程

* 預約考試時間為 10:00 ，前三十分鐘可下載 PSI Secure Browser
* 再考試前就可熙進行環境檢查。
* PSI Secure Browser 可選擇介面語系（支援繁體中文），但 **僅影響瀏覽器介面，考題仍為英文或簡中**。
* 環境檢查需先關閉背景程式，並進入排隊流程，當時前方約 20 人。
** 實際開始考試時間約為 10:25，等待時間約 40 分鐘。
** 第二次考試前面排隊人數為三，上完廁所後就已經進場準備了

==== 身分驗證與環境檢查

* 全程幾乎不需開口說話，僅一開始測試麥克風。
* 考官以「繁體中文文字訊息」進行溝通。
* 會要求檢查：
** 耳朵
** 眼鏡
** 手部
** 四周環境
** 桌上與桌下
* 系統提供「使用手機鏡頭檢查環境」的選項（本次未使用）。
* 會確認手機位置並要求關閉：
** 初次放在包包內未通過
** 經兩次詢問後，需將手機取出、關機，並展示給考官確認才通過
* 確認完成後，考官會提醒：
** 這是「最後一次上廁所的機會」

==== 考試進行過程

* 正式考試開始後：
** 題數：17 題 (15~20題)
** 考試時間：2 小時
* 考試環境內建 Firefox 瀏覽器：
** 可連線至允許的官方網站
** 不允許的網站會被直接阻擋
* 題目難度主觀感受：
** 比 kill.sh 簡單
** 比 ckx 困難
** 有考到「金絲雀部署（Canary Deployment）」
* 考題本身可切換為簡體中文。
* Firefox 內建翻譯功能可用。
* 考試途中曾被提醒一次：
** 不可遮住嘴巴
* 約考後 20 小時收到成績通知信。

===== 考題概要

* 準備很久PV跟PVC都沒考，deploy與pod內容不算多數，印象中題型為，沒印象的大概是偏向簡單類型，內容比平常模擬考題活，比較不會明講欄位跟參數。
* 第二次考試題目幾乎跟第一樣，我兩次考試間隔為兩週

. 從現有的pod的env改用 secret
. deploy fit image
. 建docker image & save
. 金絲雀部署
. deploy uid?(這題不會
. fix deploy service ingress
. cteate ingress
. create cronjob
. fix cronjob & sa
. deploy reclices & set image & rollout undo
. rbrc & sa
. networkPliocy set
. fix old deploy update now deploy

==== 補充注意事項（個人心得）

* 建議提早完成 PSI 環境檢查與排隊流程，避免影響正式進場時間。
* 桌面與四周環境務必保持淨空，避免反覆檢查延誤時間。
* 手機務必「關機」，並放置於考官可清楚確認的位置。
** 原本手機已放入包包，也須用攝影鏡頭表示放置位置
* 考試期間避免任何可能被視為遮臉、遮嘴的動作。
* 若計畫使用 Firefox 查文件，模擬環境預設打開都是k8s的docs，實際考試則不是，要熟記k8s/docs的網址

=== 多容器 Pod（Multi-container Pods）

==== 建立一個包含兩個容器的 Pod
第一個容器名稱：alpha，映像檔：nginx
第二個容器名稱：beta，映像檔：busybox，指令為 "sleep 4800"

[source,bash]
----
kubectl run alpha --image=nginx --restart=Never --dry-run=client -o yaml > multi.yaml
# 手動編輯 multi.yaml，新增第二個 container
# - name: beta
#   image: busybox
#   command: ["sleep", "4800"]

kubectl apply -f multi.yaml
----

==== 顯示 alpha Pod 中的所有容器名稱

[source,bash]
----
kubectl get po alpha -o jsonpath='{.spec.containers[*].name}'
----

==== 在 alpha Pod 內的 beta 容器中執行指令

[source,bash]
----
kubectl exec alpha -c beta -- date
----

==== 建立一個 Pod，包含一個對外開放 80 連接埠的 nginx 容器，以及一個每 5 秒寫入一次 log 的 sidecar 容器

[source,bash]
----
cat <<EOF > sidecar.yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-sidecar
spec:
  containers:
  - name: nginx
    image: nginx
    ports:
    - containerPort: 80
  - name: sidecar
    image: busybox
    command: ["sh", "-c", "while true; do echo sidecar log; sleep 5; done"]
EOF

kubectl apply -f sidecar.yaml
----

==== 顯示 sidecar 容器的 logs

[source,bash]
----
kubectl logs nginx-sidecar -c sidecar
----

=== Pod 設計（Pod Design）

==== 建立一個名為 my-namespace 的 Namespace

[source,bash]
----
kubectl create ns my-namespace
----

==== 在 my-namespace Namespace 中建立一個名為 nginx、使用 nginx 映像檔的 Pod

[source,bash]
----
kubectl run nginx --image=nginx -n my-namespace --restart=Never
----

==== 使用 YAML 檔建立相同的 Pod

[source,bash]
----
kubectl run nginx --image=nginx -n my-namespace --restart=Never --dry-run=client -o yaml > pod.yaml
kubectl apply -f pod.yaml
----

==== 在 default Namespace 建立一個名為 custom-nginx 的 Pod，使用 nginx 映像檔，並設定 CPU 需求為 200 millicores、記憶體需求為 512Mi

[source,bash]
----
kubectl run custom-nginx --image=nginx --restart=Never \
  --dry-run=client -o yaml > custom-nginx.yaml

# 編輯 custom-nginx.yaml，於 resources 區塊加上
# resources:
#   requests:
#     cpu: "200m"
#     memory: "512Mi"

kubectl apply -f custom-nginx.yaml
----

==== 建立一個名為 httpenv 的 Deployment，使用 nginx 映像檔並設定 2 個副本，定義一個名為 NGINX_PORT、值為 8080 的環境變數

[source,bash]
----
kubectl create deployment httpenv --image=nginx --replicas=2 \
  --dry-run=client -o yaml > httpenv.yaml

# 編輯 httpenv.yaml，加上
# env:
# - name: NGINX_PORT
#   value: "8080"

kubectl apply -f httpenv.yaml
----

==== 取得其中一個 httpenv Pod 的環境變數

[source,bash]
----
kubectl exec deploy/httpenv -- env
----

==== 建立一個 Pod，並將 Secret 以環境變數方式傳入
建立一個名為 mysecret，key 為 password、value 為 mypassword 的 Secret

[source,bash]
----
kubectl create secret generic mysecret --from-literal=password=mypassword
kubectl run secretpod --image=nginx --restart=Never \
  --dry-run=client -o yaml > secretpod.yaml

# 編輯 secretpod.yaml，於 containers.env 加上：
# - name: PASSWORD
#   valueFrom:
#     secretKeyRef:
#       name: mysecret
#       key: password

kubectl apply -f secretpod.yaml
----

==== 驗證 Secret 是否已以環境變數方式傳入容器

[source,bash]
----
kubectl exec secretpod -- printenv PASSWORD
----

==== 建立一個名為 myconfig 的 ConfigMap，內容為 foo=bar 與 baz=boo

[source,bash]
----
kubectl create configmap myconfig --from-literal=foo=bar --from-literal=baz=boo

#     name: myconfig

kubectl apply -f configpod.yaml
----

==== 驗證 Pod 是否已取得來自 ConfigMap 的環境變數

[source,bash]

kubectl exec configpod -- env
----

[source,yaml]

=== 狀態保存（State Persistence）

==== 建立一個名為 redis 的 Pod，使用 redis:alpine 映像檔
並掛載一個名為 redis-data 的 emptyDir Volume 至 /data

[source,bash]
----
cat <<EOF > redis.yaml
apiVersion: v1
kind: Pod
metadata:
  name: redis
spec:
  containers:
  - name: redis
    image: redis:alpine
    volumeMounts:
    - name: redis-data
      mountPath: /data
  volumes:
  - name: redis-data
    emptyDir: {}
EOF

kubectl apply -f redis.yaml
----

==== 驗證 Volume 是否已成功掛載

[source,bash]
----
kubectl exec redis -- mount | grep /data
----

==== 建立一個 PersistentVolume
容量為 1Gi，accessMode 為 ReadWriteOnce，hostPath 為 /tmp/data

[source,bash]
----
cat <<EOF > pv.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: my-pv
spec:
  capacity:
    storage: 1Gi
  accessModes:
    - ReadWriteOnce
  hostPath:
    path: /tmp/data
EOF

kubectl apply -f pv.yaml
----

==== 建立一個 PersistentVolumeClaim
請求 1Gi 儲存空間，accessMode 為 ReadWriteOnce

[source,bash]
----
cat <<EOF > pvc.yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
EOF

kubectl apply -f pvc.yaml
----

==== 建立一個名為 pvc-pod 的 Pod
將 PersistentVolumeClaim 掛載至 /data

[source,bash]
----
cat <<EOF > pvc-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: pvc-pod
spec:
  containers:
  - name: test
    image: busybox
    command: ["sh", "-c", "sleep 3600"]
    volumeMounts:
    - mountPath: /data
      name: data-vol
  volumes:
  - name: data-vol
    persistentVolumeClaim:
      claimName: my-pvc
EOF

kubectl apply -f pvc-pod.yaml
----

==== 驗證 pvc-pod 中是否已成功掛載 Volume

[source,bash]
----
kubectl exec pvc-pod -- sh -c "mount | grep /data"
----

=== Helm

==== 安裝 Helm（若尚未安裝）

[source,bash]
----
# 下載官方安裝 script
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# 驗證 Helm 版本
helm version
----

==== 新增 Helm chart repository（例如 Bitnami）

[source,bash]
----
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
----

==== 搜尋 Helm chart（例如 nginx）

[source,bash]
----
helm search repo nginx
----

==== 安裝 Helm chart（例如 nginx，可指定版本）

[source,bash]
----
helm install my-nginx bitnami/nginx
# 或指定版本
# helm install my-nginx bitnami/nginx --version 13.2.20
----

==== 列出目前所有 Helm releases

[source,bash]
----
helm list
----

==== 顯示安裝該 release 時使用的 values

[source,bash]
----
helm get values my-nginx
----

==== 升級 Helm release（指定新的設定值）

[source,bash]
----
helm upgrade my-nginx bitnami/nginx --set service.type=NodePort
----

==== 將 Helm release 回復到先前的版本

[source,bash]
----
helm rollback my-nginx 1
----

==== 移除 Helm release

[source,bash]
----
helm uninstall my-nginx
----

=== kubectl create configmap

建立 ConfigMap（CKAD 高頻）

[source,bash]
----
# 從資料夾建立（檔名會成為 key）
kubectl create configmap my-config --from-file=path/to/bar

# 指定 key 名稱
kubectl create configmap my-config \
  --from-file=key1=/path/to/bar/file1.txt \
  --from-file=key2=/path/to/bar/file2.txt

# 從 literal 建立
kubectl create configmap my-config \
  --from-literal=key1=config1 \
  --from-literal=key2=config2

# 從 env 檔建立
kubectl create configmap my-config \
  --from-env-file=path/to/foo.env \
  --from-env-file=path/to/bar.env
----

[NOTE]
====
CKAD 常考：
* ConfigMap 掛載成 volume
* ConfigMap 注入 env
* 不需要 base64（與 Secret 不同）

== CKAD 常見 YAML

=== Pod

*（單容器 + env/config/secret/探針/資源）

[source,yaml]
----
apiVersion: v1
kind: Pod
metadata:
  name: mypod
  labels:
    app: web               # 常用來讓 Service/NetworkPolicy 選到
  annotations:
    purpose: "ckad-demo"   # 考題偶爾要你加 annotation
spec:
  restartPolicy: Always    # Pod 預設 Always；Job 會用 Never/OnFailure
  imagePullSecrets:
  - name: regcred          # 若要拉私有 registry 會用到
  containers:
  - name: nginx
    image: nginx:1.27      # 明確 tag，避免 latest 導致 Always 拉
    imagePullPolicy: IfNotPresent
    ports:
    - name: http
      containerPort: 80    # expose 不會自動建 Service，僅宣告
    env:
    - name: APP_MODE
      value: "prod"        # 直接給值
    - name: PASSWORD
      valueFrom:
        secretKeyRef:      # 從 Secret 抽一個 key 變成環境變數
          name: mysecret
          key: password
    envFrom:
    - configMapRef:        # 一次把 configMap 全部鍵變成 env（KEY→VALUE）
        name: mycm
    volumeMounts:
    - name: cfg
      mountPath: /etc/app  # 將 ConfigMap 掛檔案到容器
    - name: sec
      mountPath: /etc/secret
      readOnly: true
    resources:             # 考題常要你加 requests/limits
      requests:
        cpu: "100m"
        memory: "128Mi"
      limits:
        cpu: "500m"
        memory: "256Mi"
    livenessProbe:         # 存活探針：掛了就重啟
      httpGet:
        path: /
        port: http
      initialDelaySeconds: 10
      periodSeconds: 10
    readinessProbe:        # 就緒探針：沒通不分流
      httpGet:
        path: /
        port: http
      initialDelaySeconds: 5
      periodSeconds: 5
  volumes:
  - name: cfg
    configMap:
      name: mycm           # 把 ConfigMap 變成檔案掛入
  - name: sec
    secret:
      secretName: mysecret # 把 Secret 變成檔案掛入
----

=== Deployment

* （最常考：副本/滾動更新/環境/資源/探針）

[source,yaml]
----
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mydeploy
  labels:
    app: web
spec:
  replicas: 3                     # 可被 scale 操作變更
  revisionHistoryLimit: 5         # 可回滾的歷史版本數
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1                 # 一次多出最多 1 個
      maxUnavailable: 0           # 滾更不中斷服務
  selector:
    matchLabels:                   # 必須與 template.metadata.labels 完全對上
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.27
        imagePullPolicy: IfNotPresent
        ports:
        - name: http
          containerPort: 80
        env:
        - name: APP_MODE
          valueFrom:
            configMapKeyRef:      # 只取某個鍵
              name: mycm
              key: app.mode
        resources:
          requests:
            cpu: "100m"
            memory: "128Mi"
          limits:
            cpu: "500m"
            memory: "256Mi"
        livenessProbe:
          httpGet: { path: /, port: http }
          initialDelaySeconds: 10
        readinessProbe:
          httpGet: { path: /, port: http }
          initialDelaySeconds: 5
----

* （completions/parallelism/backoff/TTL）

[source,yaml]

apiVersion: batch/v1

spec:

    spec:
      restartPolicy: Never        # Job 內的 Pod 一般用 Never/OnFailure

=== PersistentVolume (PV)

* （靜態 PV；考場常給你 hostPath/NFS）

[source,yaml]
----
apiVersion: v1
kind: PersistentVolume
metadata:
  name: mypv
spec:
  capacity:
    storage: 1Gi
  accessModes:
  - ReadWriteOnce                # 單節點讀寫；還有 RWO/ROX/RWX
  persistentVolumeReclaimPolicy: Retain  # 刪 PVC 時 PV 命運：Retain/Delete/Recycle(舊)
  storageClassName: ""           # 與動態供應區隔；空字串 = no class（靜態綁定常見）
  hostPath:                      # 測試環境常見；正式多為 NFS/Ceph/Longhorn
    path: /tmp/data
----

Solve this question on instance: `ssh ckad5601`

Create a single _Pod_ named `pod6` in _Namespace_ `default` of image `busybox:1.31.0`. The _Pod_ should have a readiness-probe executing `cat /tmp/ready`. It should initially wait 5 and periodically wait 10 seconds. This will set the container ready only if the file `/tmp/ready` exists.

==== 問題 6 | ReadinessProbe

請在 `ssh ckad5601` 的環境中完成此題。

在 `default` 命名空間建立一個名為 `pod6` 的 _Pod_，映像為 `busybox:1.31.0`。
該 _Pod_ 需設定 readiness-probe 執行 `cat /tmp/ready`，初始等待 5 秒，之後每 10 秒檢查一次。
只有當 `/tmp/ready` 檔案存在時，容器才會 Ready。

_Pod_ 需執行 `touch /tmp/ready && sleep 1d`，先建立檔案後再閒置。
請建立 _Pod_ 並確認其可啟動。

<<<
==== Answer:

[source,bash]
----
k run pod6 --image=busybox:1.31.0 --dry-run=client -oyaml --command -- sh -c "touch /tmp/ready && sleep 1d" > 6.yaml

[source,yaml]
----
# 6.yaml

kind: Pod
metadata:
  creationTimestamp: null
  labels:
    run: pod6
  name: pod6
spec:
  containers:
  - command:
    - sh
    - -c
    - touch /tmp/ready && sleep 1d
    image: busybox:1.31.0
    name: pod6
    resources: {}
    readinessProbe:                             # add
      exec:                                     # add
        command:                                # add
        - sh                                    # add
        - -c                                    # add
        - cat /tmp/ready                        # add
      initialDelaySeconds: 5                    # add
      periodSeconds: 10                         # add
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
----

| 向「下方」搜尋關鍵字（最常用，例如 /containers）

| ?關鍵字
| 向「上方」搜尋關鍵字

| n
| 跳到「下一個」符合的搜尋結果

| N
| 跳到「上一個」符合的搜尋結果

| :noh
| 清除搜尋高亮顯示（搜尋完必用，避免干擾視線）

| :set hlsearch
| 開啟搜尋結果高亮顯示（多數環境預設已開）

| :set nohlsearch
| 關閉搜尋結果高亮顯示
|===

=== grep 指令小抄

==== 基本搜尋與行數控制

[cols="1,3", options="header"]
|===
| 參數
| 說明

| -n
| 顯示行號
例：kubectl get deploy/sample-app -o yaml \| grep -n rollingUpdate

| -i
| 忽略大小寫

| -v
| 反向搜尋（排除符合字串的行）

| -c
| 只輸出符合的行數（count）

| -o
| 只輸出符合的字串
例：echo 'abcdef12345' \| grep -o '[0-9]'
|===

<<<
==== 顯示前後行（查設定必備）

[cols="1,3", options="header"]
|===
| 參數
| 說明

| -A n
| 顯示「找到行」之後 n 行（After）

| -B n
| 顯示「找到行」之前 n 行（Before）

| -C n
| 顯示前後各 n 行（Context）

| -n -A 5
| 顯示行號並包含後 5 行
例：kubectl get deploy/sample-app -o yaml \| grep -n -A 5 rollingUpdate
|===
