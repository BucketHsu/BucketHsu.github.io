== Nginx 是什麼

Nginx（通常讀作 Engine-X）是一套常用的 Web Server、反向代理伺服器與負載平衡器。

常見用途：

* 提供 HTML、CSS、JavaScript、圖片等靜態檔案。
* 將請求轉送到 Tomcat、Spring Boot、Node.js 等後端服務。
* 將流量分散到多台應用程式伺服器。
* 統一處理 HTTPS、壓縮、快取、安全 Header 與 Log。

== 正向代理與反向代理

=== 正向代理

[source,text]
----
使用者 → 正向代理 → 外部網站
----

正向代理代表用戶端知道自己透過代理連線，常見於公司對外網路控管。

=== 反向代理

[source,text]
----
使用者 → Nginx → Spring Boot / Tomcat / Node.js
----

反向代理的優點：

* 隱藏後端 IP 與 port。
* 集中管理 HTTPS。
* 依網域或路徑分流。
* 統一加入 Header、壓縮、快取與存取控制。

|程序 |用途

== 安裝與管理

=== Ubuntu / Debian

[source,bash]
----
sudo apt update
sudo apt install nginx
sudo systemctl enable --now nginx
sudo systemctl status nginx
----

=== RHEL / AlmaLinux / Rocky Linux

[source,bash]
----
sudo dnf install nginx
sudo systemctl enable --now nginx
sudo systemctl status nginx
----

=== Windows

[source,powershell]
----
cd C:\nginx
.\nginx.exe
.\nginx.exe -t
.\nginx.exe -s reload
.\nginx.exe -s quit
----

[NOTE]
====
Windows 版適合測試或簡單部署；正式 Linux 環境通常由 systemd 管理。
====

== 設定檔基本結構

[source,nginx]
----
user nginx;
worker_processes auto;

error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

events {
    worker_connections 1024;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    server {
        listen 80;
        server_name example.com;

        location / {
            root /usr/share/nginx/html;
            index index.html;
        }
    }
}
----

[cols="25%,75%", options="header"]
|===
|Context |用途

|Main
|程序、使用者、Worker、PID 與全域 Log。

|`events`
|連線處理與 Worker 連線數。

|`http`
|HTTP、HTTPS、Log、壓縮、快取與虛擬主機共用設定。

|`server`
|定義虛擬主機、監聽 port 與網域。

|`location`
|依 URL 路徑決定靜態檔案、代理或限制方式。

|`upstream`
|定義後端伺服器群組。
|===

== 修改設定的基本流程

[source,bash]
----
nginx -t
nginx -T
systemctl reload nginx
----

* `nginx -t`：檢查設定語法。
* `nginx -T`：顯示 include 展開後的完整設定。
* reload 前應先確定 `nginx -t` 成功。

== 提供靜態網站

[source,nginx]
----
server {
    listen 80;
    server_name example.com;

    root /var/www/example;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
----

=== `root`、`alias` 與 `try_files`

`root` 會把 URI 接在指定目錄後面：

[source,nginx]
----
location /files/ {
    root /data;
}
----

請求 `/files/a.pdf` 對應 `/data/files/a.pdf`。

`alias` 會以指定目錄取代 location 路徑：

[source,nginx]
----
location /files/ {
    alias /data/downloads/;
}
----

請求 `/files/a.pdf` 對應 `/data/downloads/a.pdf`。

[WARNING]
====
`location` 與 `alias` 的尾端斜線應保持一致。
====

== SPA 前端網站

React、Vue、Angular 等 SPA 通常需要將不存在的前端路由回到 `index.html`：

[source,nginx]
----
location / {
    try_files $uri $uri/ /index.html;
}
----

若網站不是 SPA，不應一律回傳 `index.html`，否則真正不存在的檔案也可能回傳 200。

== 反向代理

[source,nginx]
----
server {
    listen 80;
    server_name api.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
----

[cols="35%,65%", options="header"]
|===
|Header |用途

|`Host`
|保留原始請求網域。

|`X-Real-IP`
|傳遞直接連到 Nginx 的來源 IP。

|`X-Forwarded-For`
|保留經過多層 Proxy 的來源 IP 鏈。

|`X-Forwarded-Proto`
|告知後端原始請求是 HTTP 或 HTTPS。
|===

== `proxy_pass` 路徑規則

不包含結尾斜線：

[source,nginx]
----
location /api/ {
    proxy_pass http://127.0.0.1:8080;
}
----

`/api/users` 會轉送為 `/api/users`。

包含結尾斜線：

[source,nginx]
----
location /api/ {
    proxy_pass http://127.0.0.1:8080/;
}
----

`/api/users` 會轉送為 `/users`。

== WebSocket

[source,nginx]
----
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

location /socket/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
}
----

== Timeout 與上傳限制

[source,nginx]
----
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_connect_timeout 10s;
    proxy_send_timeout 60s;
    proxy_read_timeout 60s;
}

client_max_body_size 100m;
----

若出現 `413 Request Entity Too Large`，需同時檢查 Nginx 與後端應用程式的上傳限制。

== 負載平衡

[source,nginx]
----
upstream backend_servers {
    least_conn;
    server 10.0.0.11:8080;
    server 10.0.0.12:8080;
    keepalive 32;
}

location /api/ {
    proxy_pass http://backend_servers;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
----

`proxy_set_header Connection "";` 可避免舊版 Nginx 預設傳送 `Connection: close`，讓 upstream keepalive 能實際重用連線。

== HTTPS

[source,nginx]
----
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/private.key;
    ssl_protocols TLSv1.2 TLSv1.3;
}

server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}
----

`ssl_certificate` 通常應指定包含站台憑證與中繼憑證的完整憑證鏈。

更多憑證內容可參考 xref:security/digital-certificates-guide.adoc[數位憑證觀念與 Web Server 部署指南]。

== 安全 Header

[source,nginx]
----
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
----

HSTS：

[source,nginx]
----
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
----

[WARNING]
====
啟用 `includeSubDomains` 前，必須確認所有子網域皆支援 HTTPS。
====

== CORS

CORS 建議由單一層負責，避免後端與 Nginx 重複加入 Header。

[source,nginx]
----
location /api/ {
    if ($request_method = OPTIONS) {
        add_header Access-Control-Allow-Origin "https://frontend.example.com" always;
        add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS" always;
        add_header Access-Control-Allow-Headers "Authorization, Content-Type" always;
        add_header Access-Control-Max-Age 86400 always;
        return 204;
    }

    add_header Access-Control-Allow-Origin "https://frontend.example.com" always;

    # location 內出現 add_header 時，舊版 Nginx 不會繼承父層 add_header。
    # 因此需重複必要安全 Header，或在支援版本評估 add_header_inherit merge。
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "SAMEORIGIN" always;

    proxy_pass http://127.0.0.1:8080/;
}
----

使用 Cookie 或認證資訊時，`Access-Control-Allow-Origin` 不可設為 `*`。

== Gzip 與快取

[source,nginx]
----
gzip on;
gzip_vary on;
gzip_min_length 1024;
gzip_comp_level 5;
gzip_types text/plain text/css application/json application/javascript application/xml image/svg+xml;

location ~* \.(?:css|js|png|jpg|jpeg|gif|svg|woff2?)$ {
    expires 7d;
    add_header Cache-Control "public";
}
----

不建議壓縮 JPEG、PNG、ZIP 等已高度壓縮格式。

== Proxy Buffering

[source,nginx]
----
proxy_buffering on;
proxy_buffer_size 16k;
proxy_buffers 8 16k;
----

SSE、串流或需要即時輸出的服務，可考慮：

[source,nginx]
----
location /events/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_buffering off;
    proxy_cache off;
}
----

=== IP 白名單

[source,nginx]
----
location /admin/ {
    allow 192.168.1.0/24;
    allow 10.0.0.10;
    deny all;
}
----

=== Basic Authentication

[source,bash]
----
sudo apt install apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd admin
----

[source,nginx]
----
location /private/ {
    auth_basic "Restricted";
    auth_basic_user_file /etc/nginx/.htpasswd;
}
----

Basic Auth 應搭配 HTTPS。

== Log

[source,nginx]
----
log_format main '$remote_addr - $remote_user [$time_local] '
                '"$request" $status $body_bytes_sent '
                'request_time=$request_time '
                'upstream_time=$upstream_response_time';

access_log /var/log/nginx/access.log main;
error_log /var/log/nginx/error.log warn;
----

重要欄位：

* `$status`：HTTP 回應狀態碼。
* `$request_time`：Nginx 處理整個請求的時間。
* `$upstream_response_time`：後端回應時間。

== 常見狀態碼排查

[cols="20%,35%,45%", options="header"]
|===
|狀態碼 |常見原因 |排查方向

|403
|檔案權限、SELinux、deny 規則
|檢查執行帳號、權限與 SELinux Label。

|404
|`root`、`alias`、`location` 或 URI 錯誤
|確認實體路徑與 `try_files`。

|413
|Request Body 過大
|調整 `client_max_body_size` 與後端限制。

|499
|用戶端提前中斷
|檢查前端 timeout、網路與後端處理時間。

|502
|無法連到後端
|檢查程序、IP、port、DNS、防火牆與 SELinux。

|504
|等待後端逾時
|檢查後端效能與 `proxy_read_timeout`。
|===

== Docker Compose

[source,yaml]
----
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./nginx/certs:/etc/nginx/certs:ro
    depends_on:
      - app

  app:
    image: my-app:latest
    expose:
      - "8080"
----

同一個 Compose network 內可使用 service 名稱 `app` 連線，不應把另一個容器寫成 `127.0.0.1`。

== 正式環境檢查清單

* `nginx -t` 驗證成功。
* DNS 與防火牆設定正確。
* 憑證、私鑰與完整憑證鏈正確。
* 後端只開放必要網路範圍。
* Proxy Header 正確傳遞。
* 上傳大小與 timeout 符合需求。
* Log 有輪替與容量管理。
* HSTS、CSP、CORS 經過測試。
* 有備份與 rollback 方法。
