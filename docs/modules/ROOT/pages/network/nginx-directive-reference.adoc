本頁整理 Nginx 常用設定指令的作用範圍、用途與注意事項，適合搭配 xref:network/nginx-guide.adoc[Nginx 基礎觀念與設定指南] 查閱。

== Context 說明

[cols="20%,35%,45%", options="header"]
|===
|Context |所在位置 |用途

|Main
|設定檔最外層
|程序、使用者、Worker、PID 與全域 Log。

|`events`
|Main 內
|連線處理與 Worker 連線數。

|`http`
|Main 內
|HTTP、HTTPS、Log、壓縮、快取與虛擬主機共用設定。

|`server`
|`http` 內
|定義虛擬主機、監聽 port 與網域。

|`location`
|`server` 內
|依 URL 路徑決定靜態檔案、代理、限制或回應方式。

|`upstream`
|`http` 內
|定義後端伺服器群組。
|===

== 全域與程序設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`user nginx;`
|Main
|指定 Worker 使用的作業系統帳號。
|該帳號需能讀取靜態檔案、憑證與必要目錄。

|`worker_processes auto;`
|Main
|設定 Worker Process 數量。
|`auto` 通常依 CPU 核心數決定。

|`worker_rlimit_nofile 65535;`
|Main
|提高 Worker 可開啟檔案描述符數量。
|還需搭配 `ulimit` 或 systemd `LimitNOFILE`。

|`pid /run/nginx.pid;`
|Main
|指定 Master Process PID 檔位置。
|套件安裝通常已有預設值。

|`daemon off;`
|Main
|控制是否在前景執行。
|容器環境通常需前景執行。
|===

== Events 與連線設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`worker_connections 1024;`
|`events`
|每個 Worker 可同時處理的連線數。
|反向代理時，一個請求可能同時占用前端與後端連線。

|`use epoll;`
|`events`
|指定 Linux 高效事件模型。
|新版 Nginx 通常會自動選擇。

|`multi_accept on;`
|`events`
|讓 Worker 一次接受多個新連線。
|需搭配壓力測試。
|===

== HTTP 共用設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`include /etc/nginx/mime.types;`
|`http`
|載入副檔名與 Content-Type 對照。
|未載入可能導致 CSS、JavaScript 使用錯誤 MIME type。

|`default_type application/octet-stream;`
|`http`、`server`、`location`
|無法判斷 MIME type 時使用的預設類型。
|通常維持二進位下載類型。

|`sendfile on;`
|`http`、`server`、`location`
|使用核心機制傳送靜態檔案。
|部分網路檔案系統若更新不即時，可測試關閉。

|`keepalive_timeout 65;`
|`http`、`server`、`location`
|用戶端 Keep-Alive 保持時間。
|過長會占用連線，過短會增加 TCP/TLS 建立成本。

|`keepalive_requests 1000;`
|`http`、`server`、`location`
|單一 Keep-Alive 連線最多處理的請求數。
|高流量環境應搭配監控調整。

|`server_tokens off;`
|`http`、`server`、`location`
|隱藏回應中的 Nginx 詳細版本。
|不能取代定期更新。
|===

== Server 與網域設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`listen 80;`
|`server`
|監聽指定 IP 與 port。
|可寫成 `listen 127.0.0.1:8080;`。

|`listen 443 ssl;`
|`server`
|監聽 HTTPS。
|需搭配憑證與私鑰。

|`server_name example.com;`
|`server`
|指定虛擬主機匹配的網域。
|未匹配時可能落到同 port 的預設 server。

|`default_server`
|`listen`
|指定該 IP/port 的預設虛擬主機。
|同一組監聽位址只能有一個。

|`return 301 https://$host$request_uri;`
|`server`、`location`
|直接回傳狀態碼或重新導向。
|測試期間可先用 302，避免永久快取。

|`error_page 404 /404.html;`
|`http`、`server`、`location`
|指定自訂錯誤頁。
|避免錯誤頁本身造成循環導向。
|===

== 靜態檔案與路徑設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`root /var/www/html;`
|`http`、`server`、`location`
|將請求 URI 附加到根目錄後尋找檔案。
|`/files/a.txt` 可能對應 `/data/files/a.txt`。

|`alias /data/downloads/;`
|`location`
|以指定目錄取代 location 路徑。
|`location` 與 `alias` 尾端斜線應一致。

|`index index.html;`
|`http`、`server`、`location`
|請求目錄時依序尋找首頁檔。
|只在目錄請求時生效。

|`try_files $uri $uri/ =404;`
|`server`、`location`
|依序檢查檔案或目錄。
|SPA 常使用 `/index.html` 作為最後 fallback。

|`autoindex on;`
|`http`、`server`、`location`
|顯示目錄清單。
|正式環境通常保持關閉。
|===

== Location 比對

[cols="30%,30%,40%", options="header"]
|===
|形式 |用途 |範例

|`location = /health`
|完全相符
|健康檢查固定路徑。

|`location /api/`
|一般前綴比對
|採最長前綴。

|`location ^~ /static/`
|前綴命中後不再檢查正規表示式
|大量靜態資源目錄。

|`location ~ \.php$`
|區分大小寫正規表示式
|依副檔名處理。

|`location ~* \.(jpg|png)$`
|不區分大小寫正規表示式
|圖片快取設定。
|===

== 反向代理設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`proxy_pass http://backend;`
|`location`
|將請求轉送至後端或 upstream。
|結尾 `/` 會影響 URI 替換方式。

|`proxy_http_version 1.1;`
|`http`、`server`、`location`
|指定與後端通訊的 HTTP 版本。
|WebSocket 與 upstream keepalive 常需要 1.1。

|`proxy_set_header Host $host;`
|`http`、`server`、`location`
|覆寫傳給後端的 Header。
|通常也設定來源 IP 與原始協定。

|`proxy_connect_timeout 10s;`
|`http`、`server`、`location`
|等待與後端建立連線的時間。
|不代表完整請求總時間。

|`proxy_send_timeout 60s;`
|`http`、`server`、`location`
|向後端傳送請求的等待時間。
|大型上傳需評估。

|`proxy_read_timeout 60s;`
|`http`、`server`、`location`
|等待後端回應資料的時間。
|長任務、串流與 SSE 需調整。

|`proxy_buffering off;`
|`http`、`server`、`location`
|關閉後端回應緩衝。
|常用於 SSE 與串流。

|`client_max_body_size 100m;`
|`http`、`server`、`location`
|限制 Request Body 大小。
|需同步確認後端上傳限制。
|===

== Upstream 與負載平衡

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`upstream backend { ... }`
|`http`
|定義後端伺服器群組。
|供 `proxy_pass http://backend;` 使用。

|`server app1:8080 weight=3;`
|`upstream`
|定義後端節點與權重。
|可搭配 `max_fails`、`fail_timeout`。

|`least_conn;`
|`upstream`
|優先選擇連線數較少的後端。
|適合處理時間差異較大的請求。

|`ip_hash;`
|`upstream`
|依來源 IP 固定後端。
|來源經 Proxy 時需確認實際可見 IP。

|`keepalive 32;`
|`upstream`
|保留與後端的閒置連線池。
|舊版 Nginx 需搭配 HTTP/1.1 與 `proxy_set_header Connection "";`。
|===

== TLS 與 HTTPS

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`ssl_certificate fullchain.pem;`
|`server`
|指定站台憑證與中繼憑證鏈。
|通常應使用完整憑證鏈。

|`ssl_certificate_key private.key;`
|`server`
|指定私鑰。
|限制檔案權限，不可提交到 repository。

|`ssl_protocols TLSv1.2 TLSv1.3;`
|`http`、`server`
|限制可使用的 TLS 版本。
|應依用戶端相容性與安全政策調整。

|`ssl_session_cache shared:SSL:10m;`
|`http`、`server`
|快取 TLS Session。
|可降低重複握手成本。
|===

== Header、CORS 與安全設定

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`add_header X-Content-Type-Options "nosniff" always;`
|`http`、`server`、`location`
|加入回應 Header。
|`always` 可讓非 2xx 回應也加入。

|`add_header Strict-Transport-Security ... always;`
|`http`、`server`、`location`
|啟用 HSTS。
|啟用子網域前須確認全部支援 HTTPS。

|`add_header Access-Control-Allow-Origin ...;`
|`http`、`server`、`location`
|加入 CORS Header。
|location 內使用 `add_header` 可能停止繼承父層 Header，需重複必要 Header 或評估 `add_header_inherit merge`。
|===

== Gzip、快取與 Buffer

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`gzip on;`
|`http`、`server`、`location`
|啟用回應壓縮。
|不建議壓縮 JPEG、PNG、ZIP。

|`gzip_types ...;`
|`http`、`server`、`location`
|指定壓縮的 MIME type。
|通常包含 CSS、JSON、JavaScript、XML、SVG。

|`expires 7d;`
|`http`、`server`、`location`
|設定 Expires 與 Cache-Control。
|需配合檔名版本化策略。

|`proxy_buffer_size 16k;`
|`http`、`server`、`location`
|設定後端回應第一段 Buffer。
|Header 過大時應先檢查 Cookie 或 JWT。

|`proxy_buffers 8 16k;`
|`http`、`server`、`location`
|設定後端回應 Buffer 數量與大小。
|調整前應先觀察實際需求。
|===

== Log

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`log_format main '...';`
|`http`
|定義 Access Log 格式。
|建議包含 `$request_time` 與 `$upstream_response_time`。

|`access_log /var/log/nginx/access.log main;`
|`http`、`server`、`location`
|指定 Access Log 路徑與格式。
|需規劃 logrotate 與容量。

|`error_log /var/log/nginx/error.log warn;`
|Main、`http`、`server`、`location`
|指定 Error Log 路徑與最低等級。
|`debug` 只適合短期排查。
|===

== 存取控制與流量限制

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`allow 10.0.0.0/8;`
|`http`、`server`、`location`
|允許指定 IP 或網段。
|通常最後搭配 `deny all;`。

|`auth_basic "Restricted";`
|`http`、`server`、`location`
|啟用 HTTP Basic Auth。
|必須搭配 HTTPS。

|`limit_req_zone ...;`
|`http`
|建立請求速率限制共享區域。
|還需搭配 `limit_req`。

|`limit_req zone=api burst=20 nodelay;`
|`server`、`location`
|套用請求速率限制。
|需依正常流量壓力測試。

|`limit_conn_zone ...;`
|`http`
|建立來源連線數限制共享區域。
|還需搭配 `limit_conn`。
|===

== 真實來源 IP

[cols="25%,20%,30%,25%", options="header"]
|===
|指令 |Context |用途 |注意事項

|`set_real_ip_from 10.0.0.0/8;`
|`http`、`server`、`location`
|指定可信任的上一層 Proxy。
|不可設定成任意來源。

|`real_ip_header X-Forwarded-For;`
|`http`、`server`、`location`
|指定真實來源 IP Header。
|需配合可信任 Proxy 範圍。

|`real_ip_recursive on;`
|`http`、`server`、`location`
|從代理鏈向前尋找最後一個不可信任位址。
|依賴正確的 `set_real_ip_from`。
|===

== 常見錯誤訊息

[cols="40%,60%", options="header"]
|===
|錯誤訊息 |原因與處理

|`directive is not allowed here`
|指令放錯 Context。

|`duplicate default server`
|相同 IP/port 定義多個 `default_server`。

|`host not found in upstream`
|upstream 主機名無法解析。

|`upstream sent too big header`
|後端 Header 過大；先檢查 Cookie 或 JWT。

|`client intended to send too large body`
|Request Body 超過 `client_max_body_size`。

|`rewrite or internal redirection cycle`
|`rewrite`、`try_files` 或 `error_page` 形成循環。

|`permission denied`
|執行帳號缺少權限，或受到 SELinux 限制。
|===
